# Earlier attempts to deliver the rules that apply

The failure is not a shortage of designs. CARR has repeatedly built broader rule coverage, shorter boot text, trigger tables, semantic selection, and delivery accounting. What remains incomplete is proof that the selected rules apply: calibrated decisions on independent labels, precise binding predicates, and evaluation that cannot reuse exposed test cases. A coverage check that gives every rule a route is useful, but does not establish precision.

This archaeology was read on 2026-10-05 against fresh `origin/main` revision `b4dc32fd`, in the isolated `rule-delivery-archaeology` worktree. It made **zero Jev or other model-work calls and no production writes**. The supplied present-day baseline is 71/262 relevant deliveries (27.1% precision) and 583/717 by-turn availability (81.3%) on the 72-case test split. Those figures belong to the present study, not to the older experiments below.

The accompanying [sanitized evidence bundle](archaeology-evidence.json) contains the retained source text, read-only record responses, selected PR descriptions and latest blocking review for #1428, source hashes, and collection/query counts. Unrelated search hits and client records are omitted. PR links below are primary historical sources. A merged PR proves source delivery; it does not by itself prove current installation or live selector accuracy.

## The proposals, what shipped, and what stopped

### 1. July task loading and router-as-hook: still partly an idea

The July context audit and `sweep-sop` core-routing test proposed keeping universal context in boot and loading task context when the task needs it. Idea **32**, still open, made this mechanical: a UserPromptSubmit keyword/pattern router would inject read-first pointers for LOI, social posting and sweeps; a Stop hook would notice a client-facing draft and deliver the writing reminder. It explicitly called out reminder spam and the difference between local Claude hooks and Cowork conventions. Its second proposal was pre-action denial of unattended destructive operations, unfamiliar network sends and credential reads.

Later tool/verb/path routes and existing safeguards realize much of that mechanism, especially [#1326](https://github.com/jbookout/carr-system/pull/1326). The exact proposal's end-to-end router plus all named draft/desktop surfaces is not evidenced as completed, and the idea remains open. Its recorded reason for parking was that skills had no then-current triggering complaint and the work hardened a convention rather than fixing an observed defect. It is an ancestor, not an independent precision experiment. Idea **50**, also open, proposes backtesting lead-scoring and prospecting doctrine against record history; that is adjacent domain evaluation, not a rule-delivery selector. Its trigger is the attribute-mining/scoring debate, so it was not silently counted as delivery work.

### 2. August 2 curation and August 3 pointer decision: some proposed retirements rejected

`specs/rule-curation-plan-2026-08-02.md` proposed a compact active corpus, task grouping, separating procedures from judgment rules, collapsing duplicate countdowns and moving complete binding text into store. It proposed 54 curated rules against a then-63-rule inventory. The plan's early blockers included no deployed retire operation and no editing verb; subsequent record-layer rule lifecycle work addressed those capabilities.

This proposal was not adopted verbatim: rules it proposed retiring, including retrieval rule `113b3833`, remain in current boot. Decision **9bb9e804-85a7-4521-ada2-d749d4be558a** selected a generated one-line index with store binding text, but rejected pure pointers because an untriggered pointer does not cause a model to retrieve the rule. Decision **947ad0f7-94c2-46bc-bb6e-e05d6534e312** later narrowed mandatory reads from roughly 324 KB to 31 KB. The partial result is curation and compact indexing, not proof that all proposed removals were correct. The documented stall was missing lifecycle tooling at the time; individual still-active retirement recommendations were rejected or superseded, not merely forgotten.

Its stated reason for remaining open is sequencing across numerous small rows, not a missing grant. These August buckets are not today's inventory. They are evidence that assigning a delivery class did not finish every binding mechanism.

### 13. Exact rule routes and gated boot: coverage won, selectivity did not

## What the current climb should carry forward

1. Keep exact tool/verb/path and negative predicates, but score them against binding labels. Route coverage and pack plausibility are not labels.
2. Use the existing single selector seam. Do not resurrect the missing-caller implementation, phantom guidance consumers, or a parallel prompt hook.
3. Distinguish already-in-context availability from newly delivered relevance. The earlier boot/parity correction exposed how those denominators can change without improving behavior.
4. Keep historical serial/model-generated agreement separate from independently adjudicated accuracy. Empty or unconfirmed bands must not become calibrated confidence claims.
5. Tune only training inputs. The earlier v1–v3 ledger consulted test, and the attempted frozen-final protection is still blocked. Preserve both limitations instead of rebranding old test numbers as final.
6. Report tokens and repeated deliveries, not only provider request count. Time-based dedupe and caching reduce calls without proving one delivery per rule per session.
7. Preserve newer accepted outcomes over earlier staged records. Core compression, retirements, registry activation, selector integration and repins were built; stale loops should not make the current effort repeat them.
